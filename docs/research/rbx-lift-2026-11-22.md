### Public API of the export path

- Entry: `rbl_export::export_cancellable(dest, &[SourceTrack], &[SourcePlaylist], &[SourceMyTag], &ExportOptions, progress, cancelled) -> ExportReport`; plus `verify`, `verify_databases`, `recovery_pending`, `recover`, `estimate`, `create_library`.
- `ExportOptions`: `compatibility: Option<Wav|Aiff|Mp3>`, `cache: Option<&PreparationCache>`, `verify_all`, `keep_unlisted` (add vs mirror), `root` (PIONEER vs .PIONEER on HFS+), `expected_volume`, `defaults` (stick settings), `db_id_override`.
- `SourceTrack` is plain data: `id: u64` (stable library id, used to recognise tracks on the next sync), `source_path`, title/artist/album/genre/label/key/comment, `bpm_x100`, `duration_sec`, rating, color, year, bitrate, sample_rate, `file_size`, `artwork: Option<PathBuf>`, `cues: Option<Vec<ExportCue>>`, `metadata: ExportMetadata` (track/disc no, bit depth, play count, isrc, content_link...), and **analysis as ready ANLZ files**: `analysis: Vec<(ext, bytes)>` or `analysis_source: Option<PathBuf>`.
- `SourcePlaylist`: id, name, parent_id, folder flag, `track_indices`.

### Feeding it from library.db (pioneer-library) instead of master.db

Feasible; the hard work is analysis bytes, not metadata.
- Metadata: near 1:1 from our `Track` (title, artist, album, genre, label, comment, year, bitrate, sample_rate, file_size, duration, key). `id` = our library track id. Playlists map directly. Fields we lack (play_count, isrc, content_link, rating, color, my_tags) can be 0/empty. rbxport's own builder (`src-tauri/src/commands.rs` `source_track`) is about 50 lines; ours would be similar.
- Analysis: rbl-export copies ANLZ, it does not author it. Two routes: (1) hand it the bytes our `writer::anlz` already produces (DAT/EXT/2EX), keeping our hardware-proven ANLZ; (2) call `rbl_anlz::encode::author(ppth, &[Beat], &[BandColumn], ..)`. Our `Beat {bar_position, time_ms, tempo}` and 3-band 150 col/s columns map directly onto `Beat {beat_number, time_ms, tempo_x100}` and `BandColumn {low, mid, high, peak}`. Cues map to `ExportCue {kind, time_ms, loop_time_ms, color_id, comment}`.
- Rekordbox-shaped parts: `DeviceTrack.master_db_id`, `SyncSource`/`playlists3.sync` sync records and `content_link` mimic Rekordbox's own sync so Rekordbox accepts the stick. We would pass `db_id_override` and leave the rest default. UNVERIFIED how much of that is needed for a non-Rekordbox library.
- Hardcoded branding: manifest at `PIONEER/rbxport/manifest.json`, journal `.rbxport-publication`, `rbxport/recovered-*`. As a git dependency a fourfour stick would carry rbxport-named files and be treated as "ours" by rbxport and vice versa. A fork renames them in a few lines.

## 4. GPLv3 compatibility audit of fourfour

Method: `cargo metadata --locked` (default and `--all-features`, 683 packages incl. ort), `app/package-lock.json`, NOTICE files, model licence files. Licences as declared by each package (SPDX), not re-read from source.

- Rust crates: all permissive or weak copyleft: MIT / Apache-2.0 / BSD / ISC / Zlib / Unicode-3.0 / CC0 / Unlicense / 0BSD / NCSA (dev-only fuzz) and MPL-2.0 (symphonia 0.5 + 0.6, cssparser, selectors, option-ext; 39 crates). MPL-2.0 is GPL-compatible (section 3.3 secondary licence). r-efi is triple-licensed incl. LGPL-2.1+ (we can take MIT). **No GPL-2.0-only, no proprietary, no NC.**
- Apache-2.0-only crates: cpal, tao, flatbuffers, clang-sys, oboe, sync_wrapper, target-lexicon (LLVM exception). Compatible with **GPLv3 only, not GPLv2** (FSF).
- Native code: SQLCipher (BSD-style) + SQLite (public domain) via `bundled-sqlcipher`; crypto backend is CommonCrypto (Security framework, system library) on macOS per libsqlite3-sys 0.31 `build.rs` when no OpenSSL dir is set, system OpenSSL 3 (Apache-2.0) elsewhere. ONNX Runtime binaries via ort `download-binaries` (MIT). CoreML/WebKit are system libraries.
- npm runtime deps: `@tauri-apps/api`, `@tauri-apps/plugin-dialog` (MIT OR Apache-2.0); Svelte runtime compiled into the bundle (MIT). Dev tools irrelevant.
- Signalsmith Stretch + signalsmith-linear (vendored): MIT.
- Beat This! code and weights: MIT (`scripts/mac/LICENSE-beat-this.txt`). Upstream README warns some training data is copyrighted or limited CC; affects their data, not our licence choice (UNVERIFIED legal view, same caveat as today).
- Key model: fitted numbers from FSL10K (CC BY 4.0, which FSF lists as GPLv3-compatible) and CC BY 3.0 / CC0 loops plus FMA clips; attribution file ships. CC BY 3.0 is not formally GPL-compatible, but only derived numbers ship with credits: low risk (UNVERIFIED legal view). cyanbox port: BSD-2; libKeyFinder constants (GPL-3.0) quoted as data: fine under GPLv3, a mild issue only under a v2-only licence.
- baken waveform rules: MIT (NOTICE). Fine.
- Python `analysis/` CLI (Essentia AGPL-3.0, mutagen GPL-2.0+, torch BSD): dev tool, not shipped in the app; AGPL-3.0 combines with GPLv3 anyway.
- Our crates: `pioneer-usb-writer`, `pioneer-library`, `pioneer-test-ui` have no `license` field; `fourfour-stretch` says MIT, `fourfour-analysis-rs` MIT OR Apache-2.0; no root LICENSE. These must be set when relicensing.
- Copyright holders: git shows two authors only (Merlin 1979 commits, morizkraemer 41). Relicensing needs just the two of you.

**Verdict: no blockers.** Everything shipped is compatible with GPL-3.0-or-later.

### Recommended licence: GPL-3.0-or-later

1. GPL-2.0-only is impossible: cpal, tao and flatbuffers are Apache-2.0-only, which GPLv2 cannot combine with.
2. GPL-2.0-or-later would be legal for our source files, but every shipped binary still has to be distributed under v3 because of those Apache crates, so "v2" would be a label with no effect.
3. rbxport's GPL-2.0-or-later code can be taken into a GPL-3.0-or-later project (the "or later" lets us use it under v3). The reverse (them taking our code) needs v3 on their side; rbxport already allows that.
4. v3 adds the patent licence and anti-tivoisation terms; nothing in our distribution (notarised DMG, no locked hardware) conflicts with them.

Mechanics when decided (not done here): root `LICENSE` (GPL-3.0 text), `license = "GPL-3.0-or-later"` in all five crates (fourfour-stretch and fourfour-analysis-rs can stay MIT as standalone crates, the app as a whole is GPL), file headers on any lifted rbxport file with Chris Le's copyright, NOTICE entry for rbxport, update `THIRD-PARTY-NOTICES.txt`.

## 5. Recommendation

Option (c): port pieces into Mo's writer, in this order: staged publication + recovery, Verify, Max Compatibility conversion, exportExt.pdb. It keeps the CDJ-3000-proven format bytes, each piece is hardware-testable alone, and avoids the rusqlite 0.40 workspace bump and upstream churn of (a)/(b). Revisit (b) only if we later want PRO DJ LINK (rbl-prolink, rbl-dbserver, rbl-nfs have no rbl deps and lift cleanly; rbl-link does not, it is built on their library index).
