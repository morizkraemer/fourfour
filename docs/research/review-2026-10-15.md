## Riskiest code

- Analysis can't ship: `pioneer-test-ui/src/main.rs:255-266` `resolve_python()` bakes `CARGO_MANIFEST_DIR/analysis/.venv` at compile time; needs torch, essentia, librosa, deeprhythm.
- Sync not crash-safe: `pioneer-usb-writer/src/writer/filesystem.rs` deletes removed files before rewriting export.pdb / exportLibrary.db in place; no temp + rename.
- Change detection is size-only (`writer/sync.rs:42`); analysis changes are not compared.
- `wipe_usb` (`main.rs:935-955`) removes `PIONEER/` and `Contents/` on any path, no removable-volume check.
- `sync_playlists_to_library` (`main.rs:~775-795`) deletes and recreates all playlists, no transaction.
- Product name / bundle id: "Pioneer Test UI", `com.pioneer.test-ui`.

## Hardest problems, ranked

1. Analysis packaging + accuracy vs Rekordbox (grid phase, key, phrases). XL.
2. Format correctness across players/firmware; only oracle is hardware. M for CDJ-3000, L beyond.
3. Loss-safe incremental sync on pulled exFAT/FAT32 drives. M.
4. Packaging, signing, notarisation (SQCipher, universal build, embedded runtime). L, depends on 1.
5. Colour waveform variants PWV3–7. M.
6. Large-library performance (10k+ tracks, per-track Python process). M.
7. Legal + format churn: SQLCipher key, Pioneer trademark, Essentia AGPL. S to decide, ongoing.

## Ship blockers, in order

1. Analysis can't run on a user's Mac.
2. No signed/notarised build.
3. No CDJ-3000 check of a current export (Merlin).
4. Sync crash-safety and change detection.
5. Name, bundle id, licences.
6. Production IPC capabilities (only dev URL listed, unverified) and `wipe_usb` guard.
