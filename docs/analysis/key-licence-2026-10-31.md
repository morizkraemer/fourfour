# Licence-clean key model (run item 8), 2026-10-31

Branch from `ov-1028` (includes b7-keybar). Goal: a version of the key stage whose every fitted number comes from a permissively licensed source, and what it costs in accuracy. Follows Q46 / Q49 in [key-licence-2026-10-27.md](key-licence-2026-10-27.md), which tried synthetic and MIDI-rendered audio.

**Result: the clean model scores 56.3% exact on the Beatport test split (112 of 199), against 60.3% (120) for the shipped cyanbox port. Dev: 59.4% against 66.4%.** It is below the 60% bar, so the default is unchanged. The clean model ships in the code behind a switch (`cyankey::CLEAN_FSL`), ready if Merlin decides the licence matters more than 4 to 7 points.

New this round: a real-audio, permissively licensed, key-annotated set in an EDM-like domain exists: the **Freesound Loop Dataset (FSL10K)**. 671 loops are usable after the licence filter.

### FSL10K: what was taken

- `annotations.zip` (1.5 MB): 4,420 expert annotations of 2,936 loops; each has `key` and `mode` (`maj` / `min` / `none`).
- Kept a loop when every annotator who rated it gave the same key and mode (233 loops have two or more agreeing annotators), the loop is CC0 or CC BY 3.0 per `metadata.json`, and the audio exists. Dropped: 1,659 with no key, 437 where annotators disagree, 134 CC BY-NC, 34 Sampling+, and 1 file that does not decode. **671 loops left: 58.7% minor, 278 Freesound uploaders, median length 10 s.**
- Audio: only those 671 WAVs (984 MB) were fetched. The 8.8 GB `FSL10K.zip` was read with HTTP range requests (`benchmark/scripts/key-lab/httpzip.py`), so the rest was never downloaded.
- Attribution: CC BY 3.0 loops need the uploader credited; the list is in `fsl-clean.json` (generated by `fslselect.py`). The dataset itself is CC BY 4.0 (cite Ramires et al., ISMIR 2020).

## Options

Front end unchanged throughout: the cyanbox port in `fourfour-analysis-rs/src/cyankey.rs` (tuning, whitened 72 semitone bands, x^0.75 compression, three 12-bin chroma bands, 72 template weights plus a major bias). Only the numbers in the scoring stage change.

**Option A: theory profiles only.** Each profile is mean-centred and unit-normed per mode and used as the template for all three bands. Variants: optional harmonic smearing (Gómez-style, decay 0.6 or 0.8, 4 or 6 harmonics), band weights (1,1,1) / (0,1,1) / (0.5,1,1), major bias -0.2 / 0 / 0.2, and compression 0.75 / 1. Two ways of setting the free constants:
- "A rule": Krumhansl-Kessler, no harmonics, bias 0, linear bands. No choices at all.
- "A pick": best of the 324-variant grid by exact accuracy on FSL (clean).

**Option B: refit on FSL.** A transposition-equivariant multinomial logistic regression, the same form as cyanbox: 72 weights and one major bias. It uses Adam for 600 epochs, with an optional L2 pull towards a harmonic theory profile instead of towards zero. Model selection is 5-fold cross-validation on FSL, with folds grouped by uploader. Grid: compression 0.5 / 0.75 / 1, L2 1e-4 / 1e-3 / 1e-2, prior none / Krumhansl / Albrecht.
- "B shipped": compression stays at 0.75, the existing front end, so it is a drop-in template swap. Best FSL-CV within that: L2 1e-3, Krumhansl prior.
- "B strict": everything picked by FSL-CV, which lands on compression 1, L2 1e-2, Albrecht prior.

Confidence for B: temperature 1. `CAL_A` / `CAL_C` are fit by logistic regression of "out-of-fold prediction correct" on logit(p_best) over the FSL folds, and `CAL_B` (segment agreement) = 0. Loops are mostly a single 20 s segment, so agreement cannot be fit on them. The Sha'ath tie-break is off.

The `CLEAN_FSL` row was confirmed end to end in Rust (`cyankey` bin, model `clean-fsl`) with identical counts. Rust and the numpy lab agree on all 598 tracks for both models.

Readings:
- **Theory profiles alone are not competitive** (36 to 49%). Most errors are parallel major/minor (44 to 100 tracks). Harmonic smearing helps a few points on dev (best about 50%), not enough. The cyanbox templates encode the whitened spectrum's own harmonic and band structure, and a theory profile does not.
- **FSL-CV is a poor guide for full tracks.** The best theory variant scores 63.0% on FSL loops (cyanbox scores 60.4% there) but only 42.7% on Beatport test. Loops are short and often one instrument (bass-only or lead-only). Among the B variants, FSL-CV accuracy spreads only 1 to 2 points (n = 671, so within noise), while the same variants spread 52.8 to 58.3% on Beatport test. "B strict" is therefore the honest clean-protocol number, and "B shipped" is the sensible engineering default: same front end, and the strongest pull towards a published profile.
- **Adding synthetic audio hurts** (FSL-CV 61.1% -> 54.8%, Beatport test 52.3%), so it was dropped after the first configuration.
- **The model form is near its ceiling.** Even fit on 399 in-domain Beatport tracks it reaches 59.3% test, below the shipped 60.3%. The clean refit's gap to that ceiling is 3 points; the gap to shipped is 4 points (8 tracks), and the 95% interval at n = 199 is about ±7 points.
- Major bias: `CLEAN_FSL` learns -1.06 (FSL is 59% minor; cyanbox +0.442). The mode split on Beatport is: B makes 50 parallel errors on dev against 35 for cyanbox. That is the main loss.
- Confidence (`CLEAN_FSL`, FSL-fit calibration): mean confidence 0.53 vs accuracy 0.59 on dev, 0.49 vs 0.56 on test, Brier 0.22. It is slightly under-confident and usable.

## Licence status of `CLEAN_FSL`

- Templates, major bias, `CAL_A`, `CAL_C`: fit only on CC0 / CC BY 3.0 audio with CC BY 4.0 annotations (FSL10K), plus the Krumhansl-Kessler profile numbers as the L2 prior. Attribution is needed: Ramires et al. 2020 for the dataset, plus the CC BY 3.0 uploaders whose loops went in. Whether trained weights are a derivative of CC BY audio is a legal question; crediting avoids it.
- `CAL_B` = 0, temperature = 1: set by rule. The Sha'ath table is unused.
- Still not clean in the strict sense:
  1. The x^0.75 compression was chosen on Beatport dev (b7, model selection of one scalar). "B strict" removes it at a cost of 3.5 points on test.
  2. The front-end constants (whitening width 6, band ranges, 8192 FFT, 20 s segments) are cyanbox design choices in BSD-2 code. As far as the port shows, they are not fit on labels, but that is unverified.

## Switch

`fourfour-analysis-rs/src/cyankey.rs`:
- `KeyModel` holds the compression, templates, major bias, temperature, calibration and tie-break flag.
- `CYANBOX` (unchanged numbers) and `CLEAN_FSL` are the two models.
- `pub const SHIPPED: &KeyModel = &CYANBOX;` is the one-line switch.
- `detect` = `detect_with(SHIPPED, …)`, so app behaviour is identical: 120 / 199 test re-measured.
- `model_by_name("cyanbox" | "clean-fsl")` resolves a model by name.
- The `cyankey` bench bin takes the model name as its fifth argument.

## b14: FSL + unlabelled FMA (`CLEAN_FSL_FMA`), 2026-10-31

Goal: >= 60% exact on Beatport test with permissive data only. **Not reached: the new clean model scores 57.3% test (114 of 199), up from 56.3% (112). It is now `SHIPPED`** (rule: switch if test >= the current clean model). Every model choice below was made on Beatport dev; test was read once, for the final model.

| Model | Every fitted number from | Dev exact (n = 399) | Test exact (n = 199) | Test f / r / p / o |
|---|---|---:|---:|---|
| `cyanbox` | GiantSteps MTG (no licence) | 265 = 66.4% | 120 = 60.3% | 22 / 8 / 21 / 28 |
| `clean-fsl` | FSL10K CC0 / CC BY loops | 237 = 59.4% | 112 = 56.3% | 23 / 11 / 22 / 31 |
| **`clean-fsl-fma` (shipped)** | FSL10K + 2,150 unlabelled CC BY / CC0 / PDM FMA clips | **246 = 61.7%** | **114 = 57.3%** | 19 / 12 / 19 / 35 |

Rust (`cyankey` bin, model `clean-fsl-fma`, 598 tracks) gives the same counts as the numpy lab. Median detect 234 ms single thread. Confidence (`CAL_A` 1.068, `CAL_C` 0.243, fit out-of-fold on FSL with the same two-step fit inside each fold): mean 0.51 vs accuracy 0.62 on dev, 0.48 vs 0.57 on test, Brier 0.23 / 0.22, so still slightly under-confident.

How it is made: fit `clean-fsl` exactly as before (FSL loops, x^0.75, L2 1e-3 towards 3 x harmonic Krumhansl). Let it label 2,150 FMA clips (one round, hard labels). Refit the 72 template weights on FSL + the labelled clips with the major bias frozen at the FSL value (-1.0626). The clips: `fma_large` 30 s clips, genre Electronic (or an electronic sub-genre), track licence "Attribution" / "Creative Commons Attribution" / CC BY 3.0 / CC0 / Public Domain Mark per `fma_metadata/tracks.csv`, minus noise / drone / collage genres, >= 60 s tracks. 264 credited artists. Per-track record: `benchmark/manifests/fma-electronic-cc-unlabelled.json`. Credits: `scripts/mac/LICENSE-key-model.txt` (FMA section added, checked by `check-dmg.sh`), `NOTICE`.

What was tried (dev exact, n = 399; the plain FSL fit is 237):

| Idea | Best dev | Reading |
|---|---:|---|
| Pitch-roll augmentation of FSL bands (+-1 semitone) | 230 | hurts |
| Mixtures of 2-3 same-key FSL loops (2,000) | 225 | hurts; bias drifts to minor |
| Front end: 4 or 6 chroma bands, whitening 3 / 9, x^0.5 / log, per-frame norm, peak picking, time median | 226-240 | all within noise |
| L2 1e-4 ... 1e-2, priors (Krumhansl, Albrecht, Temperley, TKP, Aarden, none) | 231-243 | within noise (best comp 0.5, L2 3e-3: 243) |
| FSL filters by tags (no drums, chord-ish, no bass, multi-annotator only) | 241 | within noise |
| Quadratic features (frame-chroma covariance, transposition-equivariant) | 242 | no gain |
| FSL10K loops with a key in the uploader's name / tags | ~100 more loops, many wrong (e.g. "fm" as F minor) | not used |
| Self-training on FMA, 1 round, bias refit | 244 | |
| **Self-training on FMA, 1 round, bias frozen** | **246** | **shipped** |
| Self-training, 2-4 rounds | 227-245 | drifts: bias goes to +1.5 (FMA leans major), "other" errors grow |
| Self-training on the dance-genre subset only (449 clips) | 242 | |
| Feasibility probe: self-training on half of Beatport dev audio (labels unused), scored on the other half | +3 of 199 | removed from the lab after it pointed to FMA |

The in-domain ceiling explains why: refitting the same model on 4/5 of Beatport dev and testing on the held-out fifth gives 59.4-62.9% for every front end tried (5-fold within dev, labels used only for this ceiling probe, nothing shipped). The 36-weight linear template model needs about 1,500 labelled full EDM tracks (cyanbox's GiantSteps MTG set) to reach 66% dev; no permissively labelled set of that kind exists. Self-training on unlabelled CC audio is the only lever that moved the number, and it mostly fixes parallel major/minor errors (dev parallel 50 -> 37; test 22 -> 19).

Licence notes:
- FMA licences are what the artists chose on upload. "Attribution" without a version is taken as CC BY (any version). The share-alike, no-derivatives and non-commercial tracks were excluded.
- FMA labels are not used (FMA has none for key); the pseudo-labels come from `clean-fsl`, which is fit on FSL10K only.
- The x^0.75 compression and the front-end constants are inherited as before (see "Licence status" above).
