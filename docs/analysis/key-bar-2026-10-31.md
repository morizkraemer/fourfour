# Key bar: compressed semitone bands (run item 7), 2026-10-31

Branch from `ov-1028`. Goal: the shipped Rust key stage reaches 60% exact on the Beatport EDM Key test split without deepening the licence question (key-licence-2026-10-27.md). Grid must not get worse.

**Result: test 116 -> 120 of 199 = 58.3% -> 60.3% exact.** Dev 250 -> 265 of 399 (62.7% -> 66.4%). One algorithmic change: whitened semitone band magnitudes are raised to the power 0.75 before they are folded into chroma (`BAND_COMPRESSION` in `fourfour-analysis-rs/src/cyankey.rs`). Templates, major bias, calibration constants and everything else are unchanged.

## Splits

Beatport EDM Key (`benchmark/manifests/beatport-edm-key-keyonly-clean-full.corpus.json`, 598 tracks, CC BY-SA 4.0, evaluation only):

- dev: manifest `id % 3 != 0`, n = 399. All choices were made here.
- test: `id % 3 == 0`, n = 199. Scored once, after the choice, by the `cyankey` bin. Earlier rounds (Q16, Q46, Q49) also reported on this split, so it is held out from this run, not from the project.

## Before / after (cyankey bin, the app's `cyankey::detect`)

MIREX = exact + 0.5 fifth + 0.3 relative + 0.2 parallel. "fifth" = same mode, tonic a fifth up or down.

| Split | | Exact | Fifth | Relative | Parallel | Other | E+R+F | MIREX |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| test (199) | before | 116 = 58.3% | 21 | 8 | 22 | 32 | 72.9% | 67.0 |
| test (199) | **after** | **120 = 60.3%** | 22 | 8 | 21 | 28 | 75.4% | 69.1 |
| dev (399) | before | 250 = 62.7% | 38 | 14 | 45 | 52 | 75.7% | 70.7 |
| dev (399) | after | 265 = 66.4% | 39 | 11 | 35 | 49 | 78.9% | 73.9 |
| all (598) | before / after | 366 = 61.2% / 385 = 64.4% | | | | | 74.7% / 77.8% | |

Tracks changed: test +8 / -4, dev +20 / -5.

**Mode trade-off.** Most of the gain is in the major/minor decision, and it leans toward minor:

| Split | Major truth -> minor | Minor truth -> major |
|---|---:|---:|
| test before / after | 26 / 31 (of 60 major) | 23 / 12 (of 139 minor) |
| dev before / after | 44 / 50 (of 129 major) | 48 / 26 (of 270 minor) |

Flattening the band contrast lowers the effective weight of the template's major bias, so ties go to minor more often. Beatport EDM is about 70% minor, so that is a net win on EDM, but major-key tracks lose about 5 points. On a major-heavy library this change would help less or hurt. The same dev result is reached by keeping linear bands and setting the major bias to 0 (265/399); compression was chosen because it changes no fitted constant.

The +4 on test is inside the noise of n = 199 (95% interval about +-7 points). The bar is met, not beaten clearly.

## What was tried (dev, n = 399, exact; baseline 250)

From cached raw band rows (`keybands` bin) with a numpy model of the detector that reproduces the Rust predictions on all 598 tracks (0 mismatches).

| Change | Dev exact |
|---|---:|
| Band compression x^0.5 / 0.6 / 0.7 / **0.75** / 0.8 / 0.9 | 258 / 262 / 263 / **265** / 265 / 257 |
| x^1.5 / x^2 (sharper) | 240 / 235 |
| log(1 + g x), g = 1 / 10 | 264 / 240 |
| Major bias 0 / 0.2 / 0.3 with linear bands (shipped 0.442) | 265 / 262 / 256 |
| Compression 0.75 to 0.9 combined with bias 0 to 0.442 | 257 to 266, no stacking |
| Whitening half-width 3 / 4 / 8 / 10 (shipped 6) | 252 / 248 / 250 / 249 |
| Temporal median on bands, 3 / 5 / 9 frames (harmonic enhancement) | 242 / 242 / 239 |
| Per-frame chroma normalisation, energy weight^0 / 0.5 / 1 | 252 / 249 / 254 |
| Spectral peak mask (keep local band maxima) | 212 |
| Drop quietest 10% / 25% of frames | 247 / 254 |
| On top of x^0.75: segment voting 10 / 20 / 30 s | 256 / 255 / 264 |
| On top of x^0.75: Temperley mix 0.5 / 1 / 2 | 263 / 255 / 240 |
| On top of x^0.75: Krumhansl mix 0.5 / 1 / 2 | 257 / 252 / 245 |
| On top of x^0.75: per-frame norm; trim 5% / 10% of each end | 263; 259 / 259 |
| Mode by a theory third/sixth/seventh rule (always, or only when major and minor scores are close) | 201 to 247 |
| Ceiling: oracle mode for the predicted tonic | 300 |

Remaining errors at x^0.75 are not tuning-related (error rate is flat across |tuning| buckets) and the "other" bucket has no dominant offset.

## Cost

One `powf` per band value (72 per 0.37 s frame): well under 1 ms per track. `cyankey` median detect time 284 ms before, 226 ms after (single thread, decode excluded; the difference is box load, 24 to 32 during the runs, not the change).

## Licence status

- Code change: own code (MIT OR Apache-2.0), one constant.
- Templates, major bias, `TEMPERATURE`, `CAL_A/B/C`, Sha'ath tie-break: unchanged from the cyanbox port (BSD-2 code, constants fit on GiantSteps MTG, no licence). This run neither adds to nor removes that dependency.
- The exponent 0.75 was chosen on the Beatport dev split (CC BY-SA 4.0): one scalar picked from a sweep, model selection rather than fitting, as in Q46.
- Theory profiles tried and not used: Krumhansl-Kessler 1982, Temperley 1999 (published numbers).

